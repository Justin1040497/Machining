# 260613 输出文件名模板与输出配置生效语义

## 状态

有效。

## 背景

FrameLean 已从单一视频压缩工具扩展为本地媒体压缩与格式处理工具。默认导出文件名不能继续绑定“已压缩”这类单一动作，也不能依赖任务展示名；任务被用户重命名后，导出文件名仍应基于真实源文件路径。

同时，设置保存后需要让用户感到立即生效，但 FFmpeg 任务一旦启动，输出路径、编码参数和执行命令已经进入执行快照，中途修改会造成输出文件、通知路径和冲突递增规则不一致。

## 决策

输出文件名配置使用可编辑模板字符串，默认值为：

```text
{source}-{date}-{action}
```

v1.2.0 发布前默认值收敛为：

```text
{source}-{action}
```

模板变量只使用英文变量名：

| 变量 | 含义 |
| --- | --- |
| `{source}` | 源文件名，不含扩展名，来自源文件路径而不是任务展示名 |
| `{date}` | 当前日期，格式为 `yyyyMMdd` |
| `{version}` | 处理版本，首次处理为 `v1`，同源同类型同目的重复导入时递增为 `v2`、`v3` |
| `{action}` | 任务行为，例如压缩、转换、处理 |
| `{codec}` | 媒体编码或输出格式；视频使用 `h264 / h265`，图片和音频使用输出格式 |
| `{encoder}` | 视频编码器后端；使用 `auto / x264 / x265 / videotoolbox / nvenc / qsv / amf` |

模板规范化规则：

- 数字之间的 `x` 或 `X` 规范化为真正乘号 `×`，例如 `1920x1080` 写为 `1920×1080`。
- 普通编码器名称里的字母 `x` 保留，例如 `x264`、`x265`。
- `x{codec}` 会规范化为 `{codec}`，避免生成 `xh264` 或 `xh265`。
- `x{encoder}` 会规范化为 `{encoder}`，避免生成 `xx264` 或 `xx265`。
- `{version}` 按源文件路径、媒体类型和任务目的计算；重试同一个任务保持原版本号，重复导入同一个源文件才递增。
- 输出路径和源文件同名或目标文件已存在时，如果文件名末尾已有 `v1` / `v2` 这类版本 token，优先递增为下一个可用版本；没有版本 token 时自动追加中文括号后缀 `（1）`、`（2）`，不再使用 `-1`、`-2`。

设置保存生效语义：

- 视频 / 图片 / 音频任务配置属于“新任务默认值”，保存后用于后续新导入任务，不自动覆盖已有任务的处理参数。
- 输出配置属于“导出规则”，保存后立即刷新未开始、失败和已取消任务的输出目录与输出文件名。
- 运行中任务和暂停中的执行上下文保留当前执行快照；任务重来或下一次处理时重新读取最新输出配置。
- 通知文案应直接说明上述边界，临时通知只展示最多两行，通知中心保留完整内容。

## 影响

- 用户可以用同一套模板覆盖压缩、转换和通用处理场景。
- `{codec}` 和 `{encoder}` 的语义分离，避免把编码格式误写成软件编码器实现。
- 输出命名不再受任务展示名影响，任务重命名不会导致 `1.mp4` 这类错误导出名。
- 避免运行中 FFmpeg 进程被设置保存半途改写输出路径或命令参数。
- 设置保存反馈和通知中心记录成为解释生效范围的主要用户提示。
