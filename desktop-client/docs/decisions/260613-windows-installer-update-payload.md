# Windows 自托管更新使用当前用户安装器载荷

## 状态

有效。

## 背景

FrameLean 采用非应用商店分发，Windows 当前只支持 x64。Windows 发布包既需要保留便携 ZIP，方便用户手动下载和解压，也需要提供安装器，支持开始菜单入口、注册表安装信息、覆盖升级和后续自托管更新。

自托管更新如果直接下载 ZIP，主应用无法稳定完成覆盖安装、退出重启、版本确认和失败恢复；如果安装器允许管理员安装，后续静默更新可能在普通用户上下文中触发 UAC 或无法覆盖原安装目录。

## 决策

- Windows 正式发布入口生成两个分发产物：便携 ZIP 和 Inno Setup 安装器。
- Windows 自托管更新的首选下载载荷是签名后的 `FrameLean-v*-windows-x64-setup.exe`。
- ZIP 仅作为便携分发或手动下载备用，不作为首版自托管自动更新载荷。
- Windows 安装器固定为当前用户安装，默认目录为 `%LOCALAPPDATA%\Programs\FrameLean`。
- 安装器不提供管理员安装切换，避免普通自动更新流程触发 UAC。
- 后续自托管更新实现必须把下载进度和安装结果分开：主应用负责下载、大小校验、SHA-256 校验和签名校验；独立 updater helper 负责退出主应用、运行安装器、读取退出码、检查安装版本并重启应用。

## 原因

- 安装器可以复用 Inno Setup 的覆盖安装、注册表、快捷方式和文件替换语义，比 ZIP 更适合自动更新。
- 当前用户安装路径让首次安装、覆盖升级和后续静默更新保持同一权限模型。
- 下载进度只能证明网络传输完成，不能证明安装成功；安装成功需要安装器退出码、安装目录、注册表版本和新版本启动结果共同确认。
- 保留 ZIP 可以照顾便携使用场景，但不让自动更新链承担 ZIP 解压覆盖的额外恢复复杂度。

## 约束

- 安装器、主程序和后续 updater helper 都需要 Authenticode 签名和时间戳；未签名包会触发 SmartScreen 风险。
- 自动更新不能在主应用进程内直接覆盖主程序文件，必须由独立 updater helper 接管安装阶段。
- 任务运行中不应强制更新；主应用应先让用户稍后安装，或在可安全退出时再交给 updater。
- 安装器 silent 参数、退出码、日志、覆盖升级和卸载保留 / 清理语义需要在干净 Windows x64 环境中验证。
