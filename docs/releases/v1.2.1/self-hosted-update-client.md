# v1.2.1 自托管更新客户端

## 版本事实

FrameLean 在 v1.2.1 开发期把自托管更新客户端接入主体验。更新状态由 `appUpdateProvider` 统一管理；应用启动后会自动静默检查一次，设置页“关于”栏提供手动检查和下载入口，通知中心按版本去重展示更新通知，工作台顶部在存在更新或下载任务时保留持续入口。

客户端构建时通过 `FRAMELEAN_UPDATE_BASE_URL` 注入服务地址。未配置该值时使用 `NoopAppUpdateClient`，用户不会看到可下载更新。

## 交互边界

- 设置页“关于”栏主按钮根据状态显示 `检查更新`、`检查中`、`现在更新`、下载百分比、`继续 xx%`、`重启更新` 或错误后的重试入口。
- 检查到新版本后，通知中心使用 `update:{platform}:{version}:{buildNumber}` 作为去重键，同一版本跨重启只保留一条更新通知。
- 工作台顶部入口不直接开始下载，而是打开版本日志弹窗；下载中以圆形进度展示。
- 版本日志页面读取服务端发布日志列表；当服务端列表为空但当前检查结果带有日志时，回退展示当前更新的日志。
- 下载使用短期 ticket 解析出的 COS 预签名 URL，支持本地断点续传并在完成后校验 SHA-256。
- Windows 自动安装由随包 `FrameLeanUpdaterHelper.exe` 执行；主应用只负责下载、校验、写入 helper 请求文件、启动 helper 并退出。

## 平台边界

- `windows-x64` 是自动安装优先平台。更新载荷应为当前用户权限可静默覆盖安装的 Inno Setup 安装器。
- `macos-universal2` 可参与检查更新、展示版本日志和下载包；自动替换 `.app` 或 DMG 安装不在 v1.2.1 完成范围内。
- Linux / Web 工程目录存在，但不属于当前更新服务支持平台。

## 安全与完整性

- 下载包必须通过 SHA-256 校验后才进入待安装状态。
- 协议保留 `ed25519Signature` 字段，但客户端当前没有完成 Ed25519 验签。正式启用签名校验前，需要明确发布私钥保存位置、客户端公钥分发方式、签名缺失策略和验签失败提示。
- 更新服务地址不应写成带 `/api` 后缀的路径；客户端会自动拼接 `/api/v1/...`。

## 验证范围

- `appUpdateProvider` 状态机：自动检查、发现更新、ticket 下载、下载完成和 helper 启动。
- 设置页、通知中心、工作台顶部入口和版本日志弹窗的状态展示。
- 断点续传、下载暂停、SHA-256 校验失败和 helper 启动失败提示。
- Windows 干净环境覆盖安装、退出码和重启应用。
