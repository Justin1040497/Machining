# 媒体任务队列基础

## 所属版本

`v1.0.0`

## 当前事实

`v1.0.0` 建立了本地任务队列基础。任务保存到 SQLite，由 application 层 use case 和队列执行器控制开始、暂停、继续、取消、删除、重命名和完成状态。

## 设计方式

- `MediaTask` 表达任务身份、源文件、状态、进度、输出路径、错误信息和配置。
- Drift `tasks` 表保存可恢复状态。
- FFmpeg 原始执行日志不写入 SQLite，而是放在临时日志文件中。
- UI 通过工作台 notifier 调用 application use cases，不直接操作数据库或进程。

## 为什么这样设计

本地媒体处理任务可能耗时较长，且用户会反复开始、暂停、取消、重试。把任务状态持久化，把进程句柄保留在运行期内存，可以兼顾恢复能力和实现复杂度。

## 设计收益

- 应用重启后可以恢复任务列表和大部分任务状态。
- UI 和执行器解耦，后续可以扩展更多媒体类型。
- 失败、取消、缺失源文件等状态能统一表达。

## 边界

- 应用重启后不恢复旧 FFmpeg 进程句柄。
- `running` 残留状态后续仍需要明确恢复或重置策略。
