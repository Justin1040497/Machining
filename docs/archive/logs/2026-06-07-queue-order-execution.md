# 队列按列表顺序执行

## 问题

任务列表引入拖拽排序后，用户预期列表顺序就是队列顺序。旧队列执行器仍把内存中的已暂停执行上下文优先于 pending 任务处理，导致“已暂停 / 等待中”的状态会影响后续启动顺序，而不是完全按照列表排序。

同时底部主按钮的 tooltip 已显示“暂停所有任务”，但实际实现是遍历 running 任务并调用单任务暂停。单任务暂停会触发 `continueAfterTask()`，因此底部暂停可能暂停当前任务后立刻继续下一条，和“暂停所有任务”不一致。

## 方案

- 底部开始进入队列运行意图，后续任务自然完成后继续按实时列表顺序选择下一条可执行任务。
- 底部暂停退出队列运行意图，只暂停当前正在执行的任务，不继续下一条。
- 下一条可执行任务统一按 `sortOrder ASC, createdAt ASC` 选择，候选状态为 `pending` 或 `paused`。
- 任务行开始按钮作为插队入口：先验证目标任务可执行，再暂停当前前台任务并启动 / 恢复目标任务；插队不修改 `sortOrder`。
- 单任务暂停保留“暂停当前并继续后续队列”的语义，但本轮续跑会跳过刚暂停的任务，避免立即恢复同一个任务。

## 验证

- 覆盖底部暂停不续跑。
- 覆盖底部开始按列表顺序选择 paused / pending。
- 覆盖运行中重排后当前任务完成时按最新顺序启动下一条。
- 覆盖插队不修改列表排序。
- 覆盖插队目标不可执行时不打断当前任务。
