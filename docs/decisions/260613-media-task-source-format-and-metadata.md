# 260613 媒体任务保持原始与元数据配置

## 状态

有效。

## 背景

FrameLean 的视频、图片和音频任务都需要支持“保持原始格式”这类导入源相关配置。这个选项对用户应该表现为当前源文件的真实格式，例如 `MOV（保持原始）` 或 `3840 × 2160（保持原始）`；但底层格式枚举必须继续只表达真实输出格式，不能混入 `source` 这类 UI 模式值。

同时，图片、视频和音频都需要给用户同等的元数据控制能力。v1.2.0 发布默认值收敛为三类媒体均默认保留元数据，只有用户显式关闭时才剥离。

## 决策

- `MediaOutputFormat` 继续只保存真实格式枚举，不新增 `source` 或类似伪值。
- 视频、图片、音频配置通过 `keepOriginalOutputFormat` 表达“保持源格式”模式。
- 导入任务时按源文件扩展名解析真实 `MediaOutputFormat`，成功时写入该真实格式并开启 `keepOriginalOutputFormat`；解析失败时回退到默认固定格式并关闭保持模式。
- 任务详情下拉选项使用真实源格式值，但展示层加 `（保持原始）` 后缀；如果源格式或源分辨率已经作为保持原始选项出现，不再重复展示普通同值选项。
- 视频、图片和音频均使用 `preserveMetadata` 表达元数据保留，默认 `true`。
- 用户关闭元数据保留时，FFmpeg 输出参数显式写入 `-map_metadata -1`；默认保留时映射源文件全局元数据。
- 任务配置弹窗的初始状态必须按媒体类型读取对应配置，非视频任务不得读取视频专属编码器状态。

## 影响

- UI 能向用户清楚表达“保持原始”，同时数据模型保持可验证、可迁移和不含伪格式。
- `{source}`、`{codec}`、`{encoder}` 等输出模板变量可以继续依赖真实源路径、真实格式和解析后的编码器后端。
- 旧任务缺少 `preserveMetadata` 字段时按保留元数据处理，避免升级后行为突然改变。
- 非视频任务详情弹窗不再因读取视频配置而打不开。
